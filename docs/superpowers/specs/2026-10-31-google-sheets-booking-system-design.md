## 1. 系統願景與設計緣起 (Intent & Why)

光明診所（King's Clinic）現有形象官網已在 GitHub Pages 上線。為了提供社區病患更便捷的就診服務，並大幅減輕診所櫃檯人工電話接聽與手寫排號的負擔，本專案將建構一套**免付費雲端架構的線上預約掛號與動態門診系統**。

本系統採用 **Google 試算表（Google Spreadsheet）** 作為後台資料庫，搭配 **Google Apps Script (GAS)** 部署為無伺服器（Serverless）API，直接無縫整合進現有的 GitHub Pages 官網，達成「零伺服器維護成本」、「診所人員直接用 Excel/試算表調整排班與名額」及「患者在官方網站即可一站式預約、查詢與取消」之目標。

## 2. 目標、非目標與防禦目標 (Goals, Non-Goals, Anti-Goals)

### 目標 (Goals)
1. **動態門診時間表**：官網門診時間表（`#timetable`）資料來源直接綁定 Google 試算表，診所人員只要在試算表中調整排班或國定假日休診，官網即自動同步更新，免改網頁程式碼。
2. **精準時段與名額管控**：
   - 預約日期範圍嚴格限制於**未來 1 至 7 天**（不開放當日掛號，看診前一日截止線上預約）。
   - 各診次（早、午、晚）依試算表設定之「人數上限」開放名額，額滿時該時段自動反灰不可點選。
3. **同日防重複掛號**：同一個手機號碼在同一預約日期中，僅能持有一筆有效預約，避免重複佔用醫療資源。
4. **預約代碼與看診順序號**：
   - 預約成功後派發 **6 位純數字預約代碼**（如 `682109`），作為後續查詢與取消的身分安全驗證。
   - 系統依該診次之預約完成時間順序，自動賦予唯一的**看診順序號**（如第 1 號、第 2 號）。
5. **線上查詢與彈性取消**：
   - 患者於官網輸入「預約代碼 + 手機號碼」即可查閱預約詳情與看診順序號。
   - 允許於該門診時段開始前線上取消預約，取消後名額即時釋出回試算表供其他病患預約；門診已開始後則鎖定取消功能。

### 非目標 (Non-Goals)
- 本階段不串接線上金流刷卡（醫療掛號費與健保部分負擔一律於診所現場櫃檯結算）。
- 本階段不發送付費 SMS 簡訊；預約代碼透過「網頁完成頁（含一鍵複製）」與「選填 Email 確認信」兩種方式提供。未填 Email 且遺失代碼者，須致電診所協助。

### 防禦目標 (Anti-Goals)
- **避免資料併發衝突（Race Condition）**：嚴禁多位患者同時預約導致看診順序號重複或名額超收（透過 Apps Script `LockService` 鎖定機制徹底杜絕）。
- **避免病患個資洩漏**：查詢介面必須嚴格比對「預約代碼 + 手機號碼」雙重條件，絕不提供開放式的清單式查詢或模糊搜尋。
- **避免外部無效跳轉**：禁止將患者引導至 Google 外部頁面或原生難以適應手機的 iFrame，必須保持在 GitHub Pages 內的原生 Tailwind 介面體驗。

## 3. 架構方案評估 (Approaches Considered)

| 評估維度 | 方案 A：純 Google 試算表雙分頁 API 架構（本專案採用） | 方案 B：Google 試算表 + Google 行事曆雙軌 | 方案 C：Google 官方表單 / iFrame 嵌入 |
| :--- | :--- | :--- | :--- |
| **運作原理** | 單一 Google 試算表建立「預約紀錄」與「排班設定」雙分頁，由 Apps Script 提供 REST API | 試算表存紀錄，Apps Script 讀取並寫入 Google Calendar 行事曆 | 使用 Google Forms 或 Apps Script HTML 產出 iFrame 嵌入官網 |
| **維護成本** | **極低**：診所只需打開一份試算表即可看所有名單與調整排班 | **中**：需同時維護試算表及日曆權限與事件格式 | **低** |
| **使用者體驗** | **極佳**：100% 融入目前 GitHub Pages 官網風格，手機操作流暢 | **極佳**：與方案 A 相同 | **極差**：外觀與官網割裂，手機高度捲動常出現雙重捲軸 |
| **額滿與排隊控制** | 透過 `LockService` 即時鎖定計算，完全防止超賣與重號 | 日曆事件無法精確控制秒級併發鎖 | Google Forms 無法即時動態限制人數與反灰時段 |
| **選用決策** | ✅ **採納**：符合專案需求、最簡潔且不易出錯 | ❌ 不採納：日曆會被大量掛號事件洗版，且設定繁瑣 | ❌ 不採納：無法滿足額滿反灰與防重複規則 |

## 4. Google 試算表資料表設計 (Spreadsheet Data Schema)

試算表檔案名稱：`光明診所_預約掛號與門診管理系統`，內含兩個主要工作表（Sheets）：

### 工作表一：`排班與人數上限` (Schedule & Quota)
負責定義各星期之門診時段、醫師、上限名額及特殊休診日：

| 欄位名稱 (Header) | 欄位代碼 | 說明範例 |
| :--- | :--- | :--- |
| **星期** | `dayOfWeek` | 1 ~ 7（1 代表週一、7 代表週日） |
| **時段** | `timeSlot` | `早診` (09:00-12:00)、`午診` (15:00-18:00)、`晚診` (17:00-20:00 / 18:00-20:00) |
| **診次代碼** | `slotKey` | `morning` / `afternoon` / `evening` |
| **時段起訖** | `timeRange` | `09:00 - 12:00` |
| **主治醫師** | `doctor` | `張光明 院長` |
| **專科科別** | `specialty` | `骨科 / 復健評估` |
| **線上名額上限**| `maxQuota` | `20`（預設名額，填 0 代表不開放線上掛號） |
| **時段開始時間**| `startTime`| `09:00`（供系統判斷取消截止時間） |
| **特殊休診日期**| `closedDates`| 以逗點隔開之日期，如 `2026-11-05, 2026-11-12` |

### 工作表二：`預約紀錄` (Appointments)
每一列儲存一筆病患預約資料：

| 欄位 (Col) | 欄位名稱 | 格式範例 | 說明 |
| :--- | :--- | :--- | :--- |
| **A** | 預約代碼 | `839102` | 6 位隨機純數字，查詢取消憑證 |
| **B** | 預約日期 | `2026-11-03` | YYYY-MM-DD |
| **C** | 門診時段 | `早診` | 早診 / 午診 / 晚診 |
| **D** | 看診順序號 | `3` | 該診次遞增順序編號（第 3 號） |
| **E** | 患者姓名 | `王大明` | 患者全名 |
| **F** | 聯絡電話 | `0912345678` | 10 碼電話，用於驗證與防重複 |
| **G** | 診療項目 | `退化性關節炎階梯治療` | 預約科別與療程 |
| **H** | 主治醫師 | `張光明 院長` | 看診醫師 |
| **I** | 症狀備註 | `右膝痠痛約兩週` | 患者填寫之備註 |
| **J** | 預約狀態 | `預約成功` | `預約成功` / `已取消` / `已完成就診` |
| **K** | 建立時間 | `2026-10-31 14:00:00`| 系統時間戳記 |
| **L** | 取消時間 | `2026-11-01 10:20:00`| 取消時記錄 |
| **M** | 電子郵件 | `wang@example.com` | 選填；供寄送預約確認信與找回代碼，可留空 |

## 5. Google Apps Script API 規格 (Backend API Specifications)

GAS Web App 部署後提供單一 HTTP 端點，以 `POST` 接收 JSON 或 URL-encoded 參數（配合 CORS 轉向）：

### 1. `getSchedule`
- **目的**：供官網門診時間表（`#timetable`）以及掛號表單（`#booking`）抓取可預約日期與時段名額狀態。
- **輸入**：`{ "action": "getSchedule" }`
- **運算邏輯**：
  1. 產生今日後第 1 天至第 7 天（D+1 至 D+7）的日期清單。
  2. 依據星期幾比對排班時段，濾除休診日與特殊停診日期。
  3. 即時統計 `預約紀錄` 表中狀態為 `預約成功` 的人數。
  4. 計算 `remainingQuota = maxQuota - bookedCount`。若剩餘名額 <= 0，標記 `isFull: true`。
- **輸出**：門診總排班表，以及包含 D+1~D+7 各日各時段的即時名額矩陣。

### 2. `createBooking`
- **目的**：病患送出掛號。
- **輸入**：`{ "action": "createBooking", "date": "2026-11-03", "slotKey": "morning", "name": "王大明", "phone": "0912345678", "department": "arthritis", "notes": "..." }`
- **安全與驗證邏輯（需在 LockService 內執行）**：
  1. **前置檢核**：日期必須介於 D+1 ~ D+7 之間，否則拒絕（當日不開放）。
  2. **同日防重複掛號**：比對同日期 + 同手機，若已存在狀態為 `預約成功` 紀錄，回傳錯誤：「您在此日期已有預約掛號紀錄，不可重複預約」。
  3. **額滿防護**：統計該時段有效掛號人數，若已達 `maxQuota`，回傳錯誤：「該時段已額滿」。
  4. **號碼生成**：
     - `sequenceNumber`（看診號）：該時段目前最大看診號 + 1。
     - `appointmentCode`（預約代碼）：隨機生成不重複之 6 位純數字（如 `100000`~`999999`）。
  5. 寫入試算表新列。
- **輸出**：`{ "success": true, "appointmentCode": "839102", "sequenceNumber": 3, "date": "2026-11-03", "timeSlot": "早診 (09:00-12:00)", "doctor": "張光明 院長" }`

### 3. `queryBooking`
- **目的**：病患查詢預約進度。
- **輸入**：`{ "action": "queryBooking", "appointmentCode": "839102", "phone": "0912345678" }`
- **邏輯**：
  1. 檢索試算表中 A 欄（預約代碼）與 F 欄（電話）完全相符之資料。
  2. 判斷當前時間是否已超過預約當天該診次開始時間（`startTime`），決定 `canCancel: true/false`。
- **輸出**：預約詳細資訊（日期、時段、看診號碼、狀態、是否可取消）。

### 4. `cancelBooking`
- **目的**：病患自行取消預約。
- **輸入**：`{ "action": "cancelBooking", "appointmentCode": "839102", "phone": "0912345678" }`
- **邏輯**：
  1. 檢核身分並確認目前狀態為 `預約成功`。
  2. 比對門診時段開始時間，若已逾期則拒絕取消並提示電話聯繫櫃檯。
  3. 更新試算表 J 欄為 `已取消`，L 欄寫入取消時間。名額自動釋回。
- **輸出**：`{ "success": true, "message": "預約已成功取消" }`

### 5. `resendBooking`（忘記預約代碼之找回）
- **目的**：病患忘記預約代碼時，請系統將預約資料重寄至其預約時填寫的 Email。
- **輸入**：`{ "action": "resendBooking", "phone": "0912345678", "email": "wang@example.com" }`
- **邏輯**：
  1. 比對手機與 Email 皆相符、且狀態為 `預約成功` 且日期未過的紀錄。
  2. 將符合的預約（日期、時段、看診號、預約代碼）以 `MailApp` 寄至該 Email。
  3. **無論是否比對成功，網頁一律回覆「若資料相符，已寄出預約資料至您的信箱」**，避免被用來探測他人電話是否有預約；代碼絕不直接顯示在網頁上。
- **限制**：同一手機每 6 小時最多觸發 3 次找回（以 CacheService 計數），防止濫發信件。
- **未填 Email 者**：頁面提示「請致電診所 (02) 2821-0197 協助查詢」。

### 預約確認信（`createBooking` 與 `cancelBooking` 附帶）
- 若病患填寫 Email，預約成功後自動寄出確認信（日期、時段、看診號、預約代碼、取消方式說明）；取消成功後寄出取消通知。
- 寄信失敗不影響預約本身（僅記錄於 Apps Script 日誌）。
- 每日寄信量受 Google 帳號額度限制（一般帳號約 100 封／日），診所規模足夠。

## 6. 前端整合介面設計 (Frontend Architecture on GitHub Pages)

在 `index.html` 的改動重點：

1. **門診時間表區塊 (`#timetable`)**：
   - 預設具備優雅的靜態載入畫面。
   - 頁面載入時透過 `fetch()` 向 GAS 發送 `getSchedule`，成功後動態更新每週一至週六各診次的醫師與專科，若有國定假日停診則即時掛上提示標籤。
2. **預約掛號與查詢區塊 (`#booking`)**：
   - 設計 **Tab 切換鈕**：「線上掛號」與「查詢／取消預約」。
   - **線上掛號頁籤**：
     - 日期下拉選單僅列出 D+1 至 D+7 之有效預約日。
     - 選擇日期後，時段（早診/午診/晚診）動態載入該日的剩餘名額標籤（例如：`早診 09:00-12:00 [剩餘 5 名額]`，若額滿顯示 `[已額滿]` 並禁用點選）。
     - 表單含「電子郵件（選填）」欄位，旁註「填寫後將寄送預約確認信，忘記代碼時可由信箱找回」。
     - 送出成功後彈出精緻卡片，醒目呈現**6 位純數字預約代碼**與**看診順序號（看診號）**，並提供「複製預約資料」按鈕。
   - **查詢／取消頁籤**：
     - 提供「預約代碼（6位數字）」與「手機號碼」輸入框。
     - 設有「忘記預約代碼？」連結，展開後輸入手機與 Email，呼叫 `resendBooking` 重寄預約資料。
     - 查詢成功後展示清楚的看診憑據卡片。
     - 若尚未開診，顯示醒目的「取消本次預約」按鈕（點擊後二次確認彈窗防誤觸）。

## 7. 由開發執行者決策之細節 (Left to Builder)

以下細部項目交由後續實作階段依最佳實踐裁量：
- GAS API 部署設定檔 `gas/Code.gs` 之程式模組分割。
- 前端 `fetch()` 的 Loading 轉圈動畫與網路逾時（Timeout）友善重試提示。
- 試算表範本的預設名額預設值（建議預設每診次上限為 20 人，診所可在試算表隨時變更）。
- 離線降級（Fallback）機制：若 Google 網路逾時，前端自動切換顯示預設靜態時間表與電話預約專線。
